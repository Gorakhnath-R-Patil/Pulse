# Vendored eBPF headers

These four files are vendored, not authored by this project, so that
compiling `bpf/programs/*.c` does not depend on a system `libbpf-dev`
package being installed (versions of which drift across distros) — clang
with a BPF target is the only external requirement.

| File                  | Purpose                                                              |
|-----------------------|------------------------------------------------------------------------|
| `common.h`            | Minimal type definitions (`__u64`, `u64`, ...) and map-type enum, standing in for a full `vmlinux.h` for programs that don't need CO-RE kernel-struct access. |
| `bpf_helpers.h`       | The `SEC()` macro and related helper macros used to place programs/maps/license into ELF sections libbpf recognizes. |
| `bpf_helper_defs.h`   | Declarations for every BPF helper function (`bpf_ringbuf_reserve`, `bpf_ktime_get_ns`, ...), auto-generated from the kernel's helper documentation. |
| `bpf_tracing.h`       | The `BPF_PROG()` macro used by fentry/fexit programs (see `bpf/programs/tcp_connect.c`) to declare typed arguments instead of indexing a raw `u64[]` context. Self-contained — no CO-RE/`BPF_CORE_READ` dependency for the parts this project uses. |
| `LICENSE.BSD-2-Clause`| License covering these files (see below) — separate from this project's own Apache-2.0 license (`/LICENSE`), which does not apply to vendored third-party source. |

**Source:** copied verbatim from
[`cilium/ebpf`](https://github.com/cilium/ebpf)'s `examples/headers/`
directory (v0.22.0), which itself vendors them from libbpf. Not modified.

**Not vendored:** `bpf_endian.h` from the same upstream directory —
unused by any program in `bpf/programs/` today (`tcp_connect.c` reads
addresses as raw bytes and ports via explicit `encoding/binary` calls in
Go instead of in-kernel `bpf_ntohs`, since it needs no other in-kernel
byte-order conversion — see `docs/design/network-connect.md`). Add it
here (with the same provenance note) if a future program does.

**Regenerating for a different eBPF library version:** none of these are
generated by Pulse's own tooling; update by re-copying from a newer
`cilium/ebpf` release if the vendored helper declarations fall behind a
BPF helper Pulse needs.
